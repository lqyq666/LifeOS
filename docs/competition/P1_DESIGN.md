# LifeOS｜会持续了解你的个人 AI 伙伴 — 参赛设计文档

**一句话**：LifeOS 是一个持续了解同一个人的 AI 伙伴——通过关键追问把事情问清，用可核验的个人记忆给有依据的帮助，并让新的经历和反馈实际改变下一次帮助。智能体、工作流与 Skill 是它的实现与复用方式。

## 一、解决的问题

大学生在方向、机会与日常决策上最缺的不是信息，而是**一个了解自己、能把事情问清并陪着推进的伙伴**。通用问答给通用答案：同一句"我做的招新材料没用上，我是不是不行"，用户真正需要的是先弄清经过（打不开？交晚了？需求不符？对方没回？），再得到属于自己的下一步。现有工具要么是模板测评，要么是政策客服，要么是代写工具——都不随人变化。

## 二、产品核心循环

**用户说起一件事 → 找回相关背景与该事件 → 追问真正影响判断的缺口 → 随回答修正理解 → 给有个人依据的判断与可开始的一步 → 承接实际反馈 → 更新理解与安排 → 下次用上。**

三类信息分开处理：个人细节由用户补充或保持未知；外部要求（政策/资格）由获准来源核对或标待核实；偏好犹豫通过比较与小实验推进。记不清/不想说/稍后再说/尚未决定是四种不同的边界，均不被换着说法追问。

## 三、关键设计与信任机制

1. **逐字个人事实**：写入长期理解的每条个人事实都来自用户当轮原话的连续片段，服务器核验后保存；AI 的推测只能作为带局限说明的"待核对观察"，用户可采纳/拒绝。
2. **义务驱动的一轮完整性**：明确指令（改时间、暂停方向、要成品）当轮必须真实落地并通过服务端校验，回复与状态更新同一事务提交，附状态回执。
3. **时间语义精确**：每周 6 小时 ≠ 这周只剩 2 小时 ≠ 下周 4 小时；1.5 小时=90 分钟；未来周不覆盖当前周；无原话依据的期限绝不入库。
4. **用户控制**：更正只影响对应事实及依赖；拒绝的解释不再作为依据；精确遗忘连派生内容一起清理且不复活；跨会话记忆由用户开关。
5. **一个伙伴**：方向判断、行动计划、事件复盘是同一伙伴的内部能力，用户不切换机器人；普通问答直接答，情绪对话先倾听。

## 四、实现形态

- **本地产品（权威实现）**：单轮引擎内完成"权限核对→读背景/事件/边界→判断直接帮助或补关键问题→执行能力→校验并提交→回复+回执"的完整业务过程；React 前端含成长工作区（当前 AI 怎样理解你）与回执展开。
- **主 Skill `lifeos-personal-companion`**：把行为契约（何时追问/交付/停止、边界四态、诚实降级）与宿主能力约定（读状态、提交候选变化、事件与反馈）封装为可安装技能，在任何能访问本地产品的宿主中复用同一伙伴。
- **参赛演示（扣子）**：同一规则的独立工作流适配——意图路由（控制/知识/事实/伙伴）+ 伙伴智能体 + 引用硬校验 + 每轮回执；合成成年学生数据，与真实产品数据严格隔离。

## 五、验证方式（非演示自评）

26 个真实场景（含"相同开场、不同真实经过"四分支与反事实对照）由操作员按"问到才给"驱动真实模型执行；追问是否随回答推进、更正是否只改对应项、被拒解释是否复活，均以保存的状态前后差异与原始输出核对；失败轮原样保留。速度与成本按 20+ 真实普通样本分位数与每 100 成功轮成本计量。

## 六、当前状态与边界

已成立：追问循真实经过分化、个人理解逐字可溯、更正/拒绝/遗忘边界、同一机会对真实差异响应而对无关差异不响应、最小行动可开始、跨会话承接（授权后）、反馈改变下次建议（成本 ≤¥0.6/100 成功轮）。
未成立：首内容 p50≤3s/p95≤5s（供应商侧 TTFT 主导）；少量轮级模型输出违规由服务端正确拒绝（影响成功率）。演示入口为已部署参赛工作流（合成数据），真实产品未部署新版本。
