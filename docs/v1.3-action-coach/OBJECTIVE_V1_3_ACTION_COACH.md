# LifeOS V1.3：历史行动伙伴目标与验收

> 历史资料：2026-10-05 用户新完整校园产品目标已替代本文件的范围与实现顺序。当前唯一验收见 ../../PRODUCT.md。本文件只解释现有组件和旧证据，不能作为当前删功能或宣告整体验收的指令。

## 1. 唯一目标

把 LifeOS 做成一个**记得事情经过、会沿着关键细节深入追问、能与用户共同准备好下一步的行动伙伴**。

核心流程：用户带来困扰或反馈 → 找到对应事件 → 一起还原关键经过 → 区分事实、感受、解释和未知 → 确认当前可处理的障碍 → 共同产出可直接使用的下一步材料 → 执行后继续承接。

首要成功标准不是生成了多少卡片、几轮给出方案或填满多少字段，而是：**用户执行眼前下一步时，还剩多少必须自行设计、查找、组织语言和作决定的工作？系统是否已尽可能完成这些准备？**

“拆小”是拆到可开始、可观察、用户可承受，不是机械拆成几十个步骤，也不是声称复杂行为只有一个原因。必要的实际努力不能被承诺为零。已明确的执行请求直接协助；纯倾听、普通知识、正向经历也都是合法入口。

## 4. 新架构只保留一条核心路径

```text
认证与输入保护
  → 定位当前事件，读取有效过程记忆与必要来源
  → 一次生成本轮自然回应和最小状态变化
  → 校验相关字段、来源、版本与用户权限
  → 原子提交正式结果
  → 更新前端与可延后的索引/摘要
```

复用 React/TypeScript、现有后端、PostgreSQL、认证、图谱和虚拟伙伴。不增设多 Agent 编排、独立任务平台、人格测评或另一套学生评分系统。

本轮对话可以是在倾听、还原经过、核对矛盾、解释证据、共同起草材料或讨论下一步，不要求拆成互相调用的“专家 Agent”。状态表示本轮需要做什么，不是拿枚举给用户定性。

内部输出保持小：自然回应、来源引用、事件增量，以及确有需要时的行动草稿/经历确认候选即可。服务器生成用户身份、记录 ID 和版本；模型不能伪造它们。背景提取与当前事件更新可以共享一次输出，但不要双份保存同一事实或每轮重新生成整个档案。

行动变更只能是明确的新建、修改、沿用或结束，并指向确切记录。展示、保存与验证使用同一有效对象；“变更说明”依据已验证差异生成，不能单独声称执行了一个没有发生的修改。旧计划与实际经过分开，用户接受计划不等于已经执行。

## 5. 深入复盘：还原过程，而不是立刻给解释

主线输入：“我做了上次的行动，但对方没有使用。”

先定位原事件；有歧义就核对对象，已能准确定位时不重复询问。保留“原计划”与“实际执行”差异，不能把历史计划当成用户做过的事。

内部需要留意的过程是：最初目标、为什么选这个人、如何找到和联系、开场与具体沟通、对方表达的需求、双方约定、实际制作/行动、交付内容与时间、对方如何接触使用、对方回应、“没有使用”的判断依据。**这些不是一次发给用户的必填问卷。**

每轮追问一个关键缺口，通常一到两个紧密相关的问题。解释提问理由只需简短自然，不输出隐藏推理。用户一次给足信息就合并处理；允许补充、更正、记不清、不愿说、暂停或跳到一个当下可行的小动作。不得把拒答变成性格判断，也不得换个说法继续逼问。

例如，对“资料没人用”应能区分：未收到、打不开、交付晚、内容不匹配、没有明确需求、用了但没回、只是用户推测。这些是待核对的可能环节，不是系统预先知道的原因。用户已经说明“打不开”时，不再从头问“你觉得为什么没用”。

问够的条件：关键经过能连起来；当前结论的依据与未知清楚；眼前下一步不再依赖用户自行补一个复杂判断。无法证明唯一原因不阻止低风险行动，但必须把验证目的说清。不要为了达到固定问题数量而继续问。

复盘过程中积累的是当时的记录。最终暂定解释只在有价值时出现，明确范围和不确定性；不强制新 hypothesis，不根据一次事件断言能力、人格、稳定偏好或排除所有其他原因。

## 6. 下一步交付：具体到能开始，而不是多列几条建议

每个行动草稿只需要表达与本次相关的内容：要达到什么、从哪里开始、用什么现有材料、具体做/说什么、可观察产物、可承受投入以及什么情况下暂停。不把“对象、渠道、替代”等无关字段设成所有任务的必填项。

凡出现“去沟通、找个人问问、优化资料、验证需求”等抽象动作，继续协作到它可操作。系统能够代用户起草的消息、邮件、提纲、清单、简短代码或材料片段，要实际给出，不把这些准备工作再交回用户。

验收问法：用户还需要自行选择对象或工具吗？还需要重新写开场吗？材料是否真的存在、能打开、能复制？完成标准是否能观察？不需要继续时怎样结束？若答案影响执行，就解决；无关项不要增加。

“直接可执行”不等于自动对外执行。消息由用户确认后自己发送；没有真实工具操作不得说已经发出、报名或完成。占位符不得伪装成成品：缺必要内容就明确询问或给可填写模板，不能声称用户不需再准备。

### 完整示例的预期区别

合成事实：用户联系了说资料很乱的同学，未确认具体需要；花三小时整理四十页，考试前夜发网盘；对方后来明确说手机打不开，因此没看。

合格结论：已确认有打开障碍，内容有效性未检验；需求与交付时机影响仍未确定。

合格下一步：不重做四十页，先给一段可直接发送的确认消息：“上次的网盘手机打不开，我先不重发整份。你现在还需要哪一个知识点？回一个名字就行，我可以从现有资料里截一张图发你。已经不需要也没关系。”

对方明确需要某部分时，再协助用户从已有内容中选取、压缩并写使用说明；不需要就结束；没回复仅记未回复。不得把这个固定故事、用语或结论硬编码到产品。

## 7. 记忆：当前事件、可检索过程、稳定背景

当前事件是一级对象，保留目标、过程节点、材料引用、已问/已答、尚未知、用户修正和当前约定。它不因两条聊天过去就丢失；原始片段是依据，摘要只是导航。

历史事件先定位事件，再读取相关过程原文。至少支持确切事件/行动 ID、时间与对象过滤，以及自然改写的语义或混合检索。不能只把最近40条作为全部可搜索历史。检索结果仍需校验所有权、来源、修订及记忆授权，不能因相似度高就当事实。

稳定背景只保存明确、允许、相关的信息。新增过程事实不自动升级成人格或长期偏好；临时投入约束不跨事件串用；用户更正的是新版本，旧解释须同步失效或待核对。

优先复用 PostgreSQL 与一个统一检索接口。允许为真实语义召回引入一种有必要的索引/嵌入能力，或一个可替换的记忆组件；先测旧实现能否通过新检索用例，再选最小方案。不得同时接多套记忆平台，不为了品牌或“看起来成熟”换库。任何新外部服务、用户数据外传或费用须有相应授权；本地依赖调整不等于购买托管服务。

用户新消息和当前事件更新要及时可见。语义索引、合并摘要等非必需整理可异步，但必须有幂等任务、源版本和遗忘代际校验；延迟任务不能复活用户已忘记的内容。新索引未完成时，当前事件和刚提交消息仍能被下一轮读取。

明确区分：聊天留存、当前事件工作记录、跨会话记忆权限、用户确认经历。默认不借“过程记忆”绕过长期记忆开关；已发生事实可以先在当前会话整理，确认进入长期经历/图谱另行处理，不强迫每一个小细节都点一次确认。

更正/遗忘作用于原文可用性、摘要、索引、缓存和派生引用。保留必要的无内容撤回标记可防止重建；不得对用户承诺未实现的备份物理抹除。第三方聊天仅取必要片段，允许去身份化和转述，不要求上传整段私密记录。

## 8. 交互速度、输出与并发

普通复盘追问默认一次模型调用，不先串行跑问题分类、人格分析、记忆总结和第二次自查。复杂材料共创按必要程度增加输出，不让所有普通问题都使用重型推理。每个用户发送的生成/修复总计仍最多两次，自动重试为零；不要用后台调用规避台账。

实现有意义的渐进式输出，不只播放“正在思考”。可先显示普通追问的非承诺性草稿；引用敏感结论和“已保存/已执行”状态须经过相关校验。流式失败或提交失败时明确标记未保存并恢复真实状态，不能让半段输出变成正式事实。不要输出原始 JSON、内部校验器信息或隐藏推理。

输入与输出保留合理且可解释的传输上限。长粘贴不得静默截断，超限给明确分段入口；长话术或模板不得被短字段替成“参见梳理卡”。本轮不新增完整音视频解析平台。

移除实例级固定单请求瓶颈，改为可配置的有界并发与同会话写入互斥。等待可见、可取消，过载有明确反馈；用模拟 Provider 验证多账户并发、重复请求和取消，不用付费调用压测。

新的体验指标：在最终配置、明确记录网络和并发条件下，普通复盘追问至少20个真实样本，首个有意义内容 p50≤3秒、p95≤5秒，完成回复 p95≤15秒。长材料生成单列，不与普通追问混合平均；加载提示不算首个内容。数字是待达成目标，不是现有能力或生产 SLA。

若现有配置不达标，先分解检索、排队、模型首字和输出耗时，再比较已获授权的模型/模式；新供应商或购费另行授权。不能删除安全校验、伪造首字时间或用预写话术刷速度。未达体验目标须单列不通过，不称为整版完成。

## 9. 新验收：替换旧业务门槛，不删除安全证明

保留账户、来源、版本、事务、取消、幂等、已有数据读取、遗忘和图谱确认回归。行为测试覆盖目标明确时直接协助、遵守用户收入约束、规则过期时不沿用；任何安全缺陷都必须通过修复验证。

新端到端轨迹在真实运行前固定合成用户事实与可回答内容。问题措辞可变化，测试只按事先准备的对应事实回答；不让另一个模型临时编造有利用户故事，不向被测模型泄漏未告知事实。

| 轨迹 | 验收关键 |
| --- | --- |
| A01 未使用但实际打不开 | 从模糊反馈还原选人、沟通、交付、回应，确认障碍后给可发送消息；不评价内容或人格。 |
| A02 资料可打开但交付太晚 | 在用户确实提供时机证据后调整交付节奏，不复用A01的打不开结论。 |
| A03 对方明确说内容不符合需求 | 核对原需求表达与实际材料差异，协助产出一份更小的针对性材料。 |
| A04 只是没有回复 | 先核实判断依据，不把沉默当明确拒绝；尊重联系边界，不无限催促。 |
| A05 用户一次性给清楚全过程并要求写消息 | 不重新盘问，直接起草，按用户反馈改写到可以使用。 |
| A06 用户不愿复盘或只想倾听 | 尊重停止，不强迫形成行动、假设或结果卡；仍能正常聊天。 |
| A07 隔多段无关聊天后跨会话继续 | 找回准确事件、原话与未解决项；最新更正优先，不继承其他事件预算。 |
| A08 明确目标的校园执行请求 | 使用必要背景与有效规则，直接共创具体步骤/材料，不重新做人生诊断或万能问卷。 |

额外用本地可重复检索集证明：相关事件早于最近40条仍能找回；自然改写能命中；同名对象产生歧义时不猜；来源更正/删除/遗忘后不再返回旧内容；关闭记忆与跨账户请求不泄漏。语义检索至少12个预先冻结的改写查询，正确事件 Recall@3≥11/12；身份隔离和撤回项零违规。该分数仅证明此测试集，不是生产记忆准确率。

八条真实轨迹的必需行为全部满足；涉及源事实的说法能追溯；无未解决 BLOCKER/HIGH。审读必须看实际输入、可见回复、过程记录和产物，不仅看 JSON、关键词或同模型自评。下一步材料通过“用户是否还要自己设计才能开始”的审阅。已知事实无理由重复询问、关键过程未明就下因果结论、用无关计划替换用户目标均不通过。
